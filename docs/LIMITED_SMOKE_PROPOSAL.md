# Ограниченный smoke двух non-thinking профилей — предложение

Основа: main после PR #10, Issue #9 и [предложение профиля](ISSUE9_NON_THINKING_PROFILE.md). Подготовлен CLI `python -m kazakh_model_watch.non_thinking_smoke`. Реальные запросы в рамках этой работы не выполнялись; данный документ не разрешает расходы.

## Предлагаемая версия

Для будущего benchmark предлагается отдельная версия **`mvp-v2-non-thinking`**: тот же набор категорий, scoring, prompt и temperature=0 / max_output_tokens=128 / timeout_s=60 / stream=false, плюс одинаковое явное reasoning.enabled=false для обеих моделей. Имя и редакция протокола требуют согласования владельца; сейчас они не применены к спецификации или config.protocol_version.

Причина новой версии: mvp-v1 запрещает дополнительный reasoning-режим и определяет лимит именно видимого ответа. Добавление enabled=false меняет общий профиль, но не доказывает, как upstream трактует лимит. Данные разных профилей нельзя объединять в одну таблицу результатов. `MVP_SPEC.md`, dataset, readiness и profile_verified не изменяются этим CLI.

Smoke — отдельная диагностика одного фиксированного задания, не новый benchmark и не human verification. В JSON указан purpose=limited_profile_smoke, сохранены точный общий профиль и SHA256 публичного конфига. Даже полный успешный smoke не переводит модели в ready и не присваивает версию будущему benchmark.

## Предлагаемые расходы и разрешение

Предлагается согласовать **максимум два POST** — по одному `qwen/qwen3.5-9b` и `google/gemini-3.1-flash-lite`, общий разрешённый предел **USD 0.10**, без повторов и fallback. Вторая модель получает запрос только при успешных проверках первой; после остановки автоматического продолжения нет.

USD 0.10 — предложение владельцу, не подтверждённый тариф или рассчитанная стоимость. `--approved-budget-usd` записывает согласованный предел, но **не ограничивает списания провайдера программно**. CLI явно сохраняет budget_is_enforced_by_cli=false. До разрешения live нужно отдельно проверить актуальные официальные тарифы и реальный способ ограничения расходов. При невозможности обеспечить согласованный предел live не запускать. Timeout, max_tokens и отсутствие usage не являются финансовой гарантией; неуспешный запрос тоже может быть платным.

В разрешении должны быть указаны обе точные модели, максимум один запрос на каждую и общий бюджет. Подготовка CLI или его dry-run таким разрешением не считаются. Каждый новый запуск с другим run_id требует соответствующего разрешения; CLI не ведёт общий биллинговый лимит между процессами.

## Использование без сети

Из корня проекта, Windows:

```powershell
.\.venv\Scripts\python.exe -m kazakh_model_watch.non_thinking_smoke
```

На Linux/macOS использовать `.venv/bin/python`. Команда валидирует текущий config/models.json и показывает оба точных payload, не читает ключ и .env, не создаёт результаты, не конструирует адаптеры. Обе модели заранее проверяются по локальным model/endpoint metadata; для smoke допустимы not_ready, но профиль обязан включать enabled=false. Публичный metadata snapshot может устареть; require_parameters не гарантирует исполнения настройки всеми upstream.

После отдельного разрешения будущий запуск имеет форму `python -m kazakh_model_watch.non_thinking_smoke --live --approved-budget-usd <согласованный-предел> --run-id <уникальный-ID>`. Здесь это только шаблон; live не запускался. Ключ должен уже находиться в OPENROUTER_API_KEY; загрузки dotenv нет. Исторический openrouter_smoke не изменён и не подходит для проверки нового парного профиля.

## Порядок и остановки

- Фиксированный порядок Qwen → Gemini независимо от порядка записей config. Один user message с общей инструкцией и фиксированным заданием про 2+3. Dataset, accepted_answers, reference_answer и review не читаются и не передаются. Проверки качества ответа и scoring нет.
- На модель допускается один generate и не более одного POST: adapter не делает retries, redirects или fallback. Runner и его политика повторов не вызываются. Ошибка, timeout, пустой/обрезанный ответ, content_filter, неизвестный finish_reason/returned ID/HTTP status или обнаруженный reasoning останавливают сессию до следующей модели.
- Для продолжения нужны сообщённые completion_tokens ≤128 и явный нулевой reasoning counter. Неизвестные счётчики остаются неизвестными и останавливают сессию. Нулевой counter — наблюдение конкретного ответа, не гарантия отключения reasoning.
- Completion_tokens >128 останавливает сессию как диагностическая аномалия, при этом сохраняются исходные status, finish_reason и usage. Это не объявляется доказанным превышением видимого лимита и не превращает stop в length. Положительные reasoning counters не обнуляются.
- При сбое сохранения, прерывании или ошибке первого запроса второй не выполняется. После ошибки второй модели сохранённый первый результат не теряется. Нет resume, повторного использования run_id или автоматической отдельной попытки Gemini.

## Локальные артефакты

`logs/non-thinking-smoke/<run_id>/diagnostics.json`, только локально и вне Git/CI artifacts. Каталог создаётся эксклюзивно; JSON обновляется атомарно. До вызова сохраняется unfinished_attempt с неизвестным фактом HTTP-попытки: принудительно завершённый процесс не выдаёт потенциально оплаченный вызов за not_run. Не вызванная модель остаётся not_run с null usage/time.

Диагностика содержит requested/returned model ID, request ID, status, finish_reason, видимый raw response, сообщённый usage, HTTP status, статический error_code, измеренный elapsed_ms и latency_ms успешного ответа. Неизвестные поля — null, измеренный ноль сохраняется. Таймер охватывает adapter.generate без файловой записи; HTTPX timeout по-прежнему относится к сетевым фазам, общего wall-clock deadline нет.

Секреты, заголовки, exception messages, полные error bodies и reasoning-текст не записываются. Если API отражает ключ, ответ отклоняется безопасным кодом. В консоли — только безопасный summary и путь, raw response хранится локально. CLI не меняет профиль, датасет или блокировки; не пишет стоимость, scoring, leaderboard и результаты полного benchmark.
